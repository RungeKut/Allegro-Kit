# Работа с репозиторием

Набор живёт в `https://github.com/RungeKut/Allegro-Kit` и разворачивается
на нескольких машинах.

## Обязательный порядок

```bash
cd "$ALKIT_HOME"
git pull --rebase                                        # В НАЧАЛЕ работы
# ... правки набора ...
git diff                                                 # прочитать глазами
python tools/check_docs.py --project "<папка проекта>"   # стоп-слова
git add -A && git commit -m "что и почему" && git push   # СРАЗУ после правки
```

Push отклонён — `git pull --rebase`, потом push снова. **После слияния —
проверку заново и перечитать слитое**: git сливает текст, а не смысл.
Соседний набор уже получал так испорченную таблицу индекса: две строки
слились в одну. `check_docs.py` теперь считает ячейки в строках таблиц.

## Подготовка коммита: изделие в набор не попадает

Репозиторий **публичный**. Убирается всё, по чему узнаётся изделие:

* название, децимальный номер, номер платы и схемы, имена файлов проекта;
* обозначения, имена цепей, номиналы и корпуса, если они характерны;
* числа изделия: сколько компонентов и цепей, размер контура, координаты;
* надписи шелкографии, картинки платы;
* пути к папке проекта, имена серверов, учётные записи, корпоративные
  адреса почты.

**Остаётся**: поведение инструмента, командные строки, коды, примеры на
демонстрационных платах из поставки Cadence или на отвлечённой
«шестислойной плате».

### Два стоп-листа

| Файл | В репозитории | Что в нём |
|---|---|---|
| `tools/stoplist.txt` | да | только то, что не жалко опубликовать |
| `tools/stoplist.local.txt` | **нет** (`.gitignore`) | названия изделий, номера, серверы, учётные записи этой машины |

Соседний набор хранил названия изделий в публичном стоп-листе — и тем
самым их публиковал. Здесь так нельзя: новое изделие — строка в
**локальный** список до первого коммита.

`check_docs.py --project "<папка>"` добавляет к стоп-словам имя папки
проекта и имена лежащих там `.brd`, `.dsn`, `.opj`, `.sch` и т. п. Хук
`commit-msg` проверяет текст коммита по обоим спискам и по
`git config alkit.project`. Описание узла, по которому изделие узнаётся
без названия, не ловит ничего — за этим `git diff` глазами.

### Кто автор коммита

Публичный репозиторий — публичное имя. В клоне набора задаётся локально:

```bash
git config user.name  "RungeKut"
git config user.email "<публичный адрес>"
```

Иначе в историю уходит рабочее имя и корпоративный адрес из глобальных
настроек git — в соседнем наборе так ушли три коммита.

## GitHub без gh

На машине может не быть `gh`. Для публикации хватает git с сохранённым
доступом к github.com (Диспетчер учётных данных Windows) и REST API:

```bash
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')
curl -s -H "Authorization: token $TOKEN" https://api.github.com/user/repos \
     -d '{"name":"Allegro-Kit","description":"...","private":false}'
```

**`gh auth login` из агентской оболочки не запускать** — интерактивная
команда без терминала висит вечно. Нет доступа — попросить человека
выполнить вход в своём терминале.

## Установка на новой машине

```powershell
git clone https://github.com/RungeKut/Allegro-Kit.git
cd Allegro-Kit
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

Затем перезапустить Claude Code: скиллы перечисляются при старте.
