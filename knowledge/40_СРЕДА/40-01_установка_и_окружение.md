# Установка и окружение

## Состав

| Что | Где | Зачем |
|---|---|---|
| Cadence SPB 17.2-2016, hotfix S066 | `C:\Cadence\SPB_17.2` (ищется, не зашит) | Allegro, утилиты, tclsh, документация |
| Python 3.13, **64-bit** | любой | библиотека `alkit` |
| Pillow | `pip install Pillow` (ставит `setup.ps1`) | картинки платы, снимки диалогов |
| pywin32 | не нужен | окна и сообщения — через `ctypes` |

Корень Cadence ищется так: `ALKIT_CDSROOT` → `CDSROOT` →
`Sigrity_EDA_DIR` (её прописывает установщик SPB) → `C:\Cadence\SPB_*`.

## Переменные набора

| Переменная | Что | По умолчанию |
|---|---|---|
| `ALKIT_HOME` | корень набора (ставит `setup.ps1`) | — |
| `ALKIT_CDSROOT` | корень Cadence, если поиск не нашёл | поиск |
| `ALKIT_PRODUCT` | лицензии для пакетного режима, через запятую | `Allegro_performance, Allegro_Venture_PCB_Designer` из числа доступных |
| `ALKIT_WORK` | рабочие папки заданий; только ASCII, без пробелов | `%LOCALAPPDATA%\Temp\alkit` |

Лицензионный сервер задаёт установка Cadence (`CDS_LIC_FILE`), набор его
не трогает. Кэш доступных уровней —
`%HOME%\pcbenv\license_cache_allegro_17.2-2016.txt`
([30-06](../30_ГРАБЛИ/30-06_лицензии.md)).

## Подключение агентов

Набор подключают к нескольким агентам одновременно. Все они читают **один и тот
же git-репозиторий**, а не копии:

```
Allegro-Kit\                      ← git-репозиторий, единственный источник
   ├── skill\SKILL.md
   ├── knowledge\  tools\  alkit\
   ↑
   ├── ~\.claude\skills\allegro          junction   (Claude Code)
   ├── ~\.kimi-code\skills\allegro        junction   (Kimi Code)
   └── ~\.config\opencode\skills\allegro  junction   (opencode)
```

Правка файла видна всем трём агентам мгновенно — это один и тот же файл, а не
синхронизация копий. На другую **машину** правка попадает только через
`git push` отсюда и `git pull` там.

**Цель junction — `<корень>\skill`, а не корень репозитория.** В opencode
`SKILL.md` обязан лежать прямо в каталоге скила, поэтому junction на корень
скилл не найдёт, а junction на корень репозитория протащит в агента всё
вместе с `.git`. База `knowledge\`, `tools\` и библиотека `alkit\` лежат
уровнем выше; скрипты проектов находят их через `ALKIT_HOME`, а не через
каталог скила.

`tools/setup.ps1` создаёт junction'ы к Claude Code и Kimi Code. Для opencode
junction создаётся отдельно:

```powershell
cmd /c mklink /J "$env:USERPROFILE\.config\opencode\skills\allegro" `
    "<корень набора>\skill"
```

Прав администратора не требуется — junction (`mklink /J`) создаётся без них,
в отличие от символической ссылки.

**Копия набора в каталоге агента — не то же самое, что junction.** В копии
правка, сделанная одним агентом, не появится у другого, и расхождение
обнаружится через месяцы, когда исходный агент уже не работает с этим набором.

### Симлинки и hardlink

Без прав администратора и без Developer Mode символические ссылки на файлы не
создаются (`New-Item -ItemType SymbolicLink` отклоняется). Работают только:

* **junction** (`mklink /J`) — для папок;
* **hardlink** (`mklink /H`) — для файлов.

Отсюда проверка через junction выглядит иначе, чем для обычной папки.
**PowerShell 5.1 не заходит в junction при `Get-ChildItem -Recurse`** — нужен
`-FollowSymlink`, а он появился только в PowerShell 6+. Пустой вывод
`Get-ChildItem` по junction не означает, что junction сломан; проверять
надо точечно:

```powershell
Test-Path "$env:USERPROFILE\.config\opencode\skills\allegro\SKILL.md"
```

`tools/check_docs.py`, `Read` и `Glob` по путям внутри junction работают
нормально — ограничение относится только к рекурсивному перебору в
PowerShell 5.1.

### Требования opencode к SKILL.md

`skill/SKILL.md` — единственный файл набора, к которому opencode
предъявляет строгие требования:

| Поле | Требование |
|---|---|
| `name` | 1–64 символа, строчная латинская с одиночными дефисами, **совпадает с именем каталога скилла** (`allegro`) |
| `description` | 1–1024 символа |
| прочие поля | `license`, `compatibility`, `metadata`; неизвестные игнорируются |

**Описание обернуть в кавычки, если в нём есть `: ` — двоеточие с пробелом.**
Это единственная причина, по которой YAML-парсер рвёт значение: двоеточие с
пробелом внутри некавыченного скаляра читается как переход к отображению.
Набор споткнулся ровно на этом: описание `allegro` длиннее двух других
скиллов, и в нём впервые появилось двоеточие с пробелом.

Ошибка молчаливая: парсер не ругается, значение просто теряется, и в списке
скиллов агента набора нет — без всякого сообщения. Голый `;` YAML переваривает
без кавычек (проверено на всех трёх описаниях), но кавычки безвредны и
страхуют от `;` и `#` в будущих правках.

У лимита 1024 символа у `allegro` остаётся мало: описание занимает 923
символа. При доработке формулировки лимит исчерпывается быстро, и молча
обрезанное описание хуже, чем короткое.

## Что где в установке Cadence

| Путь | Что |
|---|---|
| `tools\bin\allegro.exe` | Allegro PCB Editor; `-nographic` работает и на Windows |
| `tools\bin\report.exe`, `artwork.exe`, `ipc2581_out.exe`, `step_out.exe`, `pdf_out.exe`, `dbdoctor.exe`, `extracta.exe` | утилиты над файлом платы ([10-04](../10_API/10-04_утилиты_отчёты_и_экспорт.md)) |
| `tools\bin\tclsh.exe`, `orDb_Dll_Tcl64.dll` | чтение схем Capture ([10-03](../10_API/10-03_схемы_capture_через_tcl.md)) |
| `share\pcb\examples\wm_copydata\allegro_sendcmd.c` | пример живого канала ([10-02](../10_API/10-02_живой_режим_wm_copydata.md)) |
| `share\pcb\examples\skill\` | примеры AXL-SKILL от Cadence |
| `share\orcad\examples\pcbdesign\pcbdemo1\` | демо-пара `DEMOJ.Dsn` + `allegro\DEMOJ-complete.brd` — на ней идут `tests\` |
| `doc\algroskill\` | справочник AXL (HTML), глава 2 — атрибуты объектов |
| `doc\sklangref\` | язык SKILL |
| `doc\orctclsample\`, `doc\orctclcap\` | TCL API Capture с примерами |
| `doc\algcmdref\` | команды строки Allegro |

Документация — HTML на тысячи страниц; для поиска её удобно один раз
перевести в текст (регулярка по тегам) и искать `grep`.
