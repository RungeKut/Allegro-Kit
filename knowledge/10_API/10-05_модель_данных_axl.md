# Модель данных AXL

Справочник атрибутов — `doc/algroskill/02dbdesc.html` (таблицы 2-1…2-52).
Здесь — то, что проверено и на что опирается `alkit/skill/alkit.il`.

## Чтение

| Откуда | Что взято |
|---|---|
| `axlGetParam("paramDesign")` | `->units` (millimeters, mils…), `->accuracy`, `->bBox` — поле чертежа, не плата |
| `axlDBGetDesign()` | `->components`, `->symbols`, `->nets`, `->drcs`, `->designOutline->bBox` — габарит контура платы |
| `axlGetParam("paramLayerGroup:ETCH")->groupMembers` | слои меди по порядку сверху вниз |
| компонент | `->name` (refdes), `->deviceType`, `->package`, `->class`, `->prop->VALUE`, `->symbol` (nil — не размещён) |
| символ | `->refdes`, `->name` (корпус), `->type` (PACKAGE…), `->xy`, `->rotation`, `->isMirrored` (t — на нижней стороне), `->bBox`, `->pins` |
| вывод | `->number`, `->xy`, `->net`, `->name` (падстек), `->isThrough`, `->bBox` |
| цепь | `->name`, `->unconnected`, `->unplaced`, `->nBranches` |

**Цепь фигуры на пустой цепи — строка `""`, а не объект:** `fig->net->name`
на ней падает. Проверять `stringp` (в alkit — `akNetName`).

## Все фигуры: проводники, линии, переходные, полигоны

Отдельного списка «все линии слоя» у дизайна нет. Рабочий приём:

```lisp
vis = axlVisibleGet()
axlVisibleDesign(t)                         ; выбор видит только видимое
axlClearSelSet()
axlSetFindFilter(?enabled   list("noall" "clines" "lines" "vias" "shapes")
                 ?onButtons list("noall" "clines" "lines" "vias" "shapes"))
axlAddSelectAll()
objs = axlGetSelSet()
axlClearSelSet()
axlVisibleSet(vis)                          ; вернуть видимость человеку
```

Приходят объекты `path` (сегменты — `->segments`, у каждого `->startEnd`,
`->width`, у дуги `->xy` центра и `->isClockwise`), `line`, `arc`, `via`,
`shape`, а ещё **`polygon`** — незаполненный многоугольник: так бывает
задан сам контур платы. **У такого `polygon` поле `->vertices` — nil**,
хотя документация его обещает; есть `->segments` (линии и дуги) и
`axlPolyFromDB`. У `shape` вершины — тоже через `axlPolyFromDB`. Вершина —
пара `((x y) радиус)`, радиус 0 — прямой участок.

Слой фигуры — `->layer` строкой «КЛАСС/ПОДКЛАСС»: `ETCH/TOP`,
`BOARD GEOMETRY/OUTLINE`, `PACKAGE GEOMETRY/SILKSCREEN_TOP`.

## Правка

```lisp
mark = axlDBTransactionStart()
axlTransformObject(sym ?move list(dx dy))                 ; относительный сдвиг
axlTransformObject(sym ?angle 90.0 ?origin sym->xy)       ; поворот на угол
axlTransformObject(sym ?mirror t ?origin sym->xy)         ; на другую сторону
axlDBCreateText("T" 10.0:10.0
    make_axlTextOrientation(?textBlock "1" ?rotation 0.0 ?justify "LEFT")
    "BOARD GEOMETRY/SILKSCREEN_TOP" nil)
axlDBTransactionCommit(mark)          ; или axlDBTransactionRollback(mark)
axlSaveDesign(?design "C:/work/out" ?noConfirm t)   ; путь без .brd
```

* `axlTransformObject` возвращает новый dbid; старый после правки
  перечитывать заново (`akFindSym`).
* Порядок внутри одного вызова — перенос, отражение, поворот
  (документация); `akPlace` делает их отдельными вызовами: сторона, перенос,
  поворот — и проверено, что итог совпадает с заказанным.
* Отказ AXL-функции не всегда исключение: бывает строка `\e … ERROR(…)`
  в журнале и `nil` в ответ. Поэтому `akPlace` и `akText` сами проверяют
  возврат и бросают `error()` — иначе транзакция закоммитила бы
  полуправку.
* `axlSaveDesign` в пакетном режиме пишет файл без вопросов, в том числе
  для платы старого формата
  ([30-09](../30_ГРАБЛИ/30-09_старая_плата_и_обновление_формата.md)).

## Чем подтверждено

24.09.2026: выгрузка демо-платы — 351 компонент, 2669 выводов, 14926
сегментов, 1216 переходных, 4496 полигонов; контур — два `polygon`
(`DESIGN_OUTLINE` и `OUTLINE`) с `isRect=nil`, `nSegs=14`, `vertices=nil`,
`axlPolyFromDB` — 14 вершин;
`akPlace` перенёс, повернул на 90° и перевёл на нижнюю сторону три
компонента — перечитка показала ровно заказанное; откат транзакции по
ошибке проверен в живом режиме.
