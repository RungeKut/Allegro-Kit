# DSNlck после TCL

## Что происходит

`GetDesignAndSchematics` кладёт рядом со схемой `<ИМЯ>.DSNlck` (16 КБ).
Скрипт, который вышел, не закрыв сессию, оставляет этот файл навсегда.
Что сделает Capture со схемой, рядом с которой лежит чужой `.DSNlck`, —
не проверялось; ожидаемо — предупреждение о занятой схеме, хотя её никто
не держит.

## Как правильно

1. Схема копируется в папку задания, TCL работает с копией
   ([20-01](../20_ПРИЁМЫ/20-01_работать_на_копии.md)) — блокировка, даже
   брошенная, остаётся там.
2. Сессия закрывается всегда:

```tcl
$ses RemoveDesign $des
DboTclHelper_sDeleteSession $ses
```

`alkit/tcl/dsn_dump.tcl` делает оба пункта.

## Как неправильно

```tcl
set des [$ses GetDesignAndSchematics [DboTclHelper_sMakeCString $orig] $st]
# ... чтение ...
exit                   ; сессия не закрыта, DSNlck остался у оригинала
```

## Чем подтверждено

24.09.2026: разведочный скрипт обхода вхождений открыл демо-схему прямо в
папке поставки и вышел без `RemoveDesign` — рядом остался `DEMOJ.DSNlck`
(удалён вручную). В папках заданий `ak.read_dsn` после трёх разных схем
файлов `.DSNlck` нет.
